# AI腔人话转换器·一键切换

总入口。**用户说了用哪个版本，就直接用；没说，就判断该用哪个。**

## 第一步：检查是否已指定

用户这句话里如果已经出现版本名或调用名，直接按那个版本走，不再判断：

| 用户说的 | 直接用 |
|----------|--------|
| 通用版 / 白描改写 / humanizer-chinese | 通用版 |
| 学术版 / humanizer-academic | 学术版 |
| 营销版 / humanizer-marketing | 营销版 |
| 文学创作版 / humanizer-literary | 文学创作版 |
| 社交媒体版 / humanizer-social | 社交媒体版 |
| 包袱版 / humanizer-baofu | 包袱版 |

「用学术版润色这段」「用包袱版改这个段子」「humanizer-marketing 处理一下」——都是显式指定，别多问。

## 第二步：没指定时判断

按下面的顺序判断，命中即停：

1. **有明确发布平台吗？**（小红书/公众号/知乎/微博/抖音/朋友圈）→ 社交媒体版。但如果核心是一个段子，走包袱版做内核，社交版做封装——见交叉规则。
2. **以笑果为首要目标吗？**（段子/笑话/脱口秀/相声/包袱/好笑）→ 包袱版。
3. **是学术场景吗？**（论文/摘要/文献/投稿/基金/学位论文）→ 学术版。
4. **是商业文案吗？**（卖点/广告语/详情页/CTA/转化）→ 营销版。
5. **是文学创作吗？**（小说/散文/诗歌/对白/剧本）→ 文学创作版。
6. **都不是** → 通用版。

判断依据来自文本特征和上下文，不是单个关键词。用户说「改个小红书段子」，两个特征都有——见交叉规则。

### 可以用脚本辅助

仓库里有 `scripts/route_version.py`，输入文本输出推荐版本、置信度、命中词：

```bash
python3 scripts/route_version.py "帮我看看这段论文摘要"
python3 scripts/route_version.py --file draft.md
echo "写个小红书段子" | python3 scripts/route_version.py
```

脚本是规则匹配，给的是参考。语义判断优先于脚本结果。两者冲突时，按语义判断走，并说明为什么。

## 第三步：告诉用户推荐，再动手

**不要默默切换。** 用一句话说清推荐和理由：

> 这段是论文摘要，用学术版处理——它会守住事实、引文、结论三不变。

然后按该版本的 SKILL.md 规则执行。

**例外**：用户说「别问了直接改」「你看着办」——跳过确认，直接按推荐版本处理。

**低置信度时**（文本特征模糊、多个版本得分接近），先问一句：

> 这段看起来像是要发小红书，也可能按通用版改就行。你要哪种？

## 第四步：按该版本机制执行

各版本的专属机制见 `版本机制说明.md`。要点：

- **学术版**：先声明三不变和伦理风险，改写只动语言层
- **营销版**：先圈出保护对象（卖点/数据/品牌口号），再动刀
- **文学创作版**：先识别体裁 + 建作者风格档案，白名单内容不动
- **社交媒体版**：先识别平台 + 查钩子与正文是否脱节，给多标题多版本
- **包袱版**：先识别载体 + 建人物笑法档案，冷笑话白名单不误伤
- **通用版**：直接标记病灶，四步走

## 交叉规则

一个文本命中多个版本时：

| 场景 | 顺序 |
|------|------|
| 幽默广告 | 包袱版诊断笑点 → 营销版把关卖点与广告法 |
| 文学喜剧 | 包袱版定笑点结构 → 文学创作版润质感 |
| 社交平台段子 | 包袱版产笑话内核 → 社交媒体版做平台封装 |
| 学术文本里的幽默 | 学术版先过规范 → 包袱版看笑点 |

**优先级**：合规红线 > 事实不变 > 版本专属目标。

## 什么时候不动手

- 用户明确说「就用通用版」——不要自作主张升级到扩展版。
- 文本一条病灶都没有——原样退回，不管哪个版本。
- 用户要的是翻译、总结、续写，不是改写——告诉用户这不是本 skill 家族的职责。
- 2022 年 11 月 30 日之前写的文字，不是 AI 写的。

## 返回什么

- 先说一句推荐版本与理由（除非用户让直接改）
- 再按该版本的输出格式给结果
